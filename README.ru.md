**Coda** — приложение для Android, которое превращает чистый Linux-сервер в личный загрузчик музыки для
[Navidrome](https://www.navidrome.org/). Вводишь IP, логин и пароль сервера — приложение по SSH ставит Docker,
поднимает всё нужное, и дальше ты ищешь исполнителя, нажимаешь на альбом, а треки попадают в твою библиотеку
Navidrome с тегами и обложками. Движок вырос из Telegram-бота.

> **Сочетается с [vici](https://github.com/aut0iq/vici).** Coda наполняет библиотеку Navidrome, а **vici** —
> музыкальный плеер, в котором её слушают (работает с Navidrome и любым сервером Subsonic API). Вместе: Coda
> скачивает, vici играет. Оба говорят на Subsonic API, так что подойдёт и любой другой Subsonic-клиент.

## Возможности

- **Настройка с телефона** — IP, логин, пароль. Без терминала: Docker, контейнеры, HTTPS-сертификат.
- **Один сервер или два** — Navidrome рядом со скачиванием, **или** на другом сервере: сервер скачивания сам
  заходит на сервер Navidrome по SSH и кладёт файлы в указанную там папку.
- **Папку для музыки выбираешь сам** — в обоих вариантах.
- **Умное скачивание** — поиск через Deezer, звук через yt-dlp (YouTube → SoundCloud → cookies для 18+ →
  твои прокси), точный подбор по длительности и названию, теги и обложки, пропуск дублей и live-версий
  (сверяется с твоим Navidrome), плейлисты по исполнителям, очередь, которая переживает перезапуск.
- **Надёжность** — установка продолжается на сервере, даже если телефон уснул или пропала связь, а приложение
  переподключается; музыка не теряется, если сервер Navidrome временно недоступен: она ждёт и уезжает позже.
- **Честно про запреты** — если сервер в стране, где YouTube, Deezer или реестры Docker закрыты или режутся
  (например, в России), приложение скажет об этом и предложит VPN на сервере или [zapret](https://github.com/bol-van/zapret).
- **Безопасно по умолчанию** — пароль SSH нигде не хранится, API защищён токеном, ключи серверов запоминаются.

## Как это работает

<div align="center">
<img src="docs/architecture.svg" alt="Телефон → сервер скачивания → сервер Navidrome → плеер" width="100%">
</div>

1. **SSH — один раз.** Телефон подключается к *серверу скачивания*, заливает установщик и запускает его.
   Установщик ставит Docker и контейнеры: `api` (скачивание), `caddy` (HTTPS) и — при варианте «один сервер» —
   `navidrome`.
2. **Дальше — HTTPS.** Приложение работает с API сервера скачивания по токену (токен передан телефону по SSH, по
   сети он не ездит). Рабочий экран — небольшой веб-интерфейс, который раздаёт сам сервер.
3. **Два сервера?** Ты один раз вводишь SSH-логин сервера Navidrome. Сервер скачивания создаёт свой ключ, кладёт
   его в `authorized_keys` того сервера, проверяет вход по ключу и дальше пароль ему не нужен. Файлы передаются по
   SFTP под временным именем и переименовываются только после проверки размера — Navidrome не видит
   недописанных файлов; после успеха локальная копия удаляется.
4. **Слушай.** Направь **[vici](https://github.com/aut0iq/vici)** (или другой Subsonic-клиент) на свой Navidrome.

Варианты размещения:

```
Один сервер      телефон ──SSH──▶ сервер: Docker + api + navidrome + caddy ──▶ vici
Два сервера      телефон ──SSH──▶ сервер скачивания ──SFTP по SSH (по ключу)──▶ сервер Navidrome ──▶ vici
```

### Что на сервере после установки

`/opt/music-hub/` — `docker-compose.yml`, `.env` (токен и пароль Navidrome, права 600), `data/music` (библиотека,
обычные файлы; своя папка задаётся при установке и переживает обновления), `data/navidrome`, `data/hub` (очередь,
история, cookies, настройки). Порты: 80 и 443 (или один порт без HTTPS).

В режиме «два сервера» на сервере скачивания Navidrome нет: `data/stage` — промежуточная папка (музыка живёт там
только до передачи), `data/hub/ssh/id_ed25519` — ключ для входа на сервер Navidrome (600), `data/hub/remote.json` —
адрес, папка, ключ хоста и данные Navidrome (600; пароля SSH там нет).

## Скачать

Бери APK со страницы [**последнего релиза**](https://github.com/aut0iq/Coda/releases/latest) — в каждом релизе есть
сборка под каждую архитектуру процессора и универсальная:

| Файл | Кому подходит |
|---|---|
| `coda-<версия>-arm64-v8a.apk` | Почти любой телефон и планшет после ~2017 года — **начни с него** |
| `coda-<версия>-armeabi-v7a.apk` | Старые 32-битные ARM-устройства |
| `coda-<версия>-x86_64.apk` | Эмуляторы Android на ПК, Chromebook, x86-планшеты |
| `coda-<версия>-x86.apk` | Старые 32-битные x86-устройства и эмуляторы |
| `coda-<версия>-universal.apk` | Не уверен, какой выбрать? Работает везде, но файл примерно в 4 раза больше |

Открой файл на устройстве и разреши «установку из неизвестных источников» для приложения, из которого его открыл.
К релизу приложен `SHA256SUMS.txt` для проверки загрузки. APK подписаны стандартным отладочным ключом Android: для
установки напрямую подходит, для Google Play — нет.

## Быстрый старт

1. Установи APK (см. выше) или собери его сам (см. ниже).
2. Открой **Coda**, нажми «Подключить сервер», введи IP, логин и пароль свежего Linux-сервера (проверено на
   Ubuntu 24.04, другие системы семейства Debian должны подойти; root или пользователь с `sudo`) и нажми
   «Проверить сервер».
3. Выбери размещение:
   - оставь галочку **«Navidrome на этом же сервере»** — Navidrome поставится рядом (можно указать свою папку
     для музыки), **или**
   - сними её и введи адрес сервера Navidrome, SSH-логин и пароль, папку с библиотекой на нём, адрес Navidrome и
     его логин с паролем.
4. Нажми «Установить». Когда появится «Готово» — открой сервер, найди исполнителя, выбери альбом.
5. В меню приложения лежат адрес и данные Navidrome — впиши их в **vici**.

**Что нужно от сервера Navidrome (вариант «два сервера»):** Navidrome уже установлен и работает; доступ по SSH с
паролем (хотя бы на время настройки) и включённый SFTP (оболочка не нужна); пользователь SSH может писать в
папку, которая в Navidrome указана как библиотека. Установка Navidrome на такой сервер из приложения пока не
делается.

## Запреты (плашка)

Проверка идёт **на самом сервере** и в двух местах:

* **До установки** — `preflight.sh` через curl: страна, YouTube, Deezer, SoundCloud, реестры Docker
  (`registry-1.docker.io`, `ghcr.io`, `get.docker.com`). Плашка в приложении (`app/src/banner.js`).
* **После установки** — `server/api/netcheck.py`, раз в 6 часов и по кнопке: то же плюс **реальная скорость**
  отдачи аудио с googlevideo (в РФ YouTube режут, и страница открывается, а качать нельзя) и случай
  «YouTube принял сервер за бота». Плашка в мини-аппе (`webapp/ui.js`), подробности во вкладке «Ещё».

Сервер в РФ и что-то не открывается → плашка предлагает **VPN на сервере** или **zapret** (на выбор), без
автоустановки. Не РФ + «принял за бота» → советует cookies аккаунта или прокси. Если прокси из настроек решает
проблему — плашки нет.

## Безопасность

* Токен API генерирует установщик и передаёт приложению **по SSH**; хранится на телефоне в `expo-secure-store`.
* Пароль SSH не сохраняется нигде: живёт в памяти на время установки. Пароль сервера Navidrome уходит через stdin
  по уже открытому SSH — не аргументом команды и не по HTTP.
* Отпечаток ключа SSH-сервера запоминается при первом подключении; изменился — подключение обрывается. То же
  для сервера Navidrome.
* 10 неверных токенов за 10 минут — блокировка адреса на 5 минут (429).
* `/api/img` без токена (для `<img>`), но только хосты обложек Deezer.
* Без HTTPS (порты заняты) токен и пароль идут открыто — приложение предупреждает.

## Сборка

Нужны Node 22, JDK 17, Android SDK (переменная `ANDROID_HOME`) и, для тестов, [deno](https://deno.com).

```bash
cd app
npm install                       # postinstall кладёт серверную часть в src/bundle.generated.js
npx expo install --check          # версии под Expo SDK 53
npm test                          # тесты протокола установщика и пакета (нужен deno; на Windows — Git Bash)
npx expo prebuild --platform android --clean --no-install
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
# APK: app/android/app/build/outputs/apk/release/app-release.apk
```

* Для **телефона** — `arm64-v8a`, для **эмулятора на ПК** — `x86_64`.
* Проверялось на SDK 35, build-tools 35.0.0, NDK 27.1.12297006 (ровно то, что просит Expo 53).
* Пакеты `expo-asset`, `expo-constants`, `expo-font`, `expo-file-system`, `expo-keep-awake` указаны в
  `package.json` **намеренно**: новый npm кладёт их внутрь `node_modules/expo/`, автолинковка Android их там не
  видит, и приложение падает на старте (`Cannot find native module 'ExpoAsset'`).
* `expo prebuild` каждый раз сам дописывает в `package.json` скрипт `ios` — это нормально.
* После любой правки в `server/` выполни `npm run bundle` в `app/` — приложение заливает на сервер ту копию,
  что лежит в `src/bundle.generated.js`.

> Переводы строк: `.gitattributes` принудительно ставит LF. Не убирай его — `install.sh` с CRLF на Linux-сервере
> не запустится.

Проверки без телефона:

```bash
cd server/api && python -m unittest discover -s . -t . -p "test_*.py"    # 59 тестов, в том числе с настоящим SSH/SFTP-сервером
deno run --allow-read server/api/tests/ui_test.js                        # отрисовка мини-аппа
cd app && npm run bundle && npm test                                     # протокол установщика, пакет
```

Проверка на эмуляторе: он достаёт до ПК по адресу `10.0.2.2`. Тестовый «VPS» — контейнер Ubuntu 24.04 с sshd и
своим Docker (`--privileged`, порты `2222→22` и `8080→8080`); в приложении вводишь `10.0.2.2`, порт SSH `2222`,
режим «Без HTTPS на порту 8080». Образ API локально: `docker build -t music-hub-api server/api`.

### GitHub Actions

1. Тег `v0.1.0` (должен совпадать с версией в `app/package.json`) → workflow *apk* собирает пять APK (arm64-v8a,
   armeabi-v7a, x86_64, x86 и универсальный) и выкладывает их на страницу релиза вместе с `SHA256SUMS.txt`. Запуск вручную
   (Actions → *apk* → Run workflow) — те же сборки, но без релиза: файлы лежат в Artifacts.
2. Образ API: workflow *server* собирает `ghcr.io/<владелец>/music-hub-api`. **Один раз** сделай пакет публичным:
   GitHub → Packages → `music-hub-api` → Package settings → Change visibility → Public. Пока пакет приватный,
   установщик сам соберёт образ на сервере (дольше, но работает). Если владелец не `aut0iq`, поменяй
   `HUB_API_IMAGE` в `server/deploy/docker-compose*.yml`.

## Состав репозитория

| Каталог | Что |
|---|---|
| `app/` | Приложение (Expo 53 / React Native 0.79). Нативные экраны: серверы, подключение, установка; основной интерфейс — мини-апп с твоего сервера. `modules/hub-ssh` — небольшой Kotlin-модуль SSH на JSch (форк mwiede). |
| `server/api/` | Движок: Deezer + yt-dlp + теги + дубли + плейлисты, HTTP API, токен-авторизация, проверка запретов, `remote.py` (передача на другой сервер). |
| `server/deploy/` | Пакет установки: `install.sh` (идемпотентный — он же обновление), `preflight.sh`, `uninstall.sh`, compose и Caddy для обоих вариантов. |
| `docs/` | Баннер, схема, скриншоты. |

Внутренние имена (`music-hub`, `/opt/music-hub`, образ `music-hub-api`) остались от прежнего названия проекта —
их не меняли, чтобы уже установленные серверы продолжали работать.

## Что проверено

Прогнано вживую (эмулятор Android x86_64 + чистая Ubuntu 24.04 с Docker 29):

* сборка APK, нативный SSH-модуль (JSch mwiede 0.2.20): вход по паролю, ошибки «неверный пароль» / «порт закрыт»,
  проверка отпечатка ключа при обновлении;
* весь путь в приложении: подключение → проверка сервера → установка → мини-апп в WebView;
* **обрыв связи посреди установки**: установщик идёт на сервере отвязанно, приложение переподключается и читает
  журнал с того же места; по окончании журнал (в нём токен) удаляется с сервера;
* повторная установка поверх работающей (обновление): токен и пароль Navidrome сохраняются, данные целы;
* `uninstall.sh --purge`; скачивание альбома (11 треков, теги, обложка) → библиотека видна в Navidrome по Subsonic API;
* **два сервера** (сервер скачивания + отдельный сервер с рабочим Navidrome, вход под обычным пользователем):
  настройка из приложения (ключ, папка, проверка входа по ключу и самого Navidrome), скачивание альбома → файлы на
  сервере Navidrome, у сервера скачивания ничего не остаётся, Navidrome пересканирован и показывает альбом,
  плейлист создан; отказ: SSH на сервере Navidrome выключен → музыка не теряется, ждёт передачи, после
  возвращения связи уезжает, уведомление приходит один раз; обновление такого сервера без ввода данных заново;
* режим «один сервер» со **своей папкой** для музыки: установка, сохранение папки при обновлении, предупреждение
  о файлах другого владельца, `uninstall --purge` свою папку не трогает;
* тесты: 59 серверных (Windows и Linux-образ), 66 проверок у приложения, 43 — отрисовка мини-аппа.

### Не проверено

* **HTTPS через Let's Encrypt** (sslip.io / свой домен) — нужен публичный IP;
* установка **Docker с нуля** на сервере с systemd (в тестовом контейнере Docker уже был);
* RHEL-семейство и arm64-серверы;
* вход под **не-root пользователем с sudo** через само приложение (через тестовую обвязку по SSH — проверен);
* сервер в РФ и плашка о запретах на живом заблокированном сервере (логика покрыта тестами);
* первый прогон GitHub Actions и публикация образа в GHCR;
* два сервера: Navidrome за обратным прокси с доменом, нестандартные алгоритмы ключей, NAS с урезанным SFTP;
* запросы к Navidrome (дубли, пересканирование, плейлисты) идут с сервера скачивания напрямую по HTTP(S) на его
  адрес, а не через SSH-туннель: Navidrome должен быть доступен серверу скачивания по сети.
